# Запуск магазина без Docker (для учеников)

Пошагово: как запустить магазин на своём компьютере (Windows), если Docker не установлен.
Вы получите магазин и админку в обычном браузере и сможете запускать тесты.

## Что будет работать, а что нет

| Работает | Не работает без интернет-адреса и настоящего бота |
|---|---|
| каталог, корзина, оформление заказа, заказы | открытие магазина внутри Telegram |
| админка: товары, фото, заказы, курьеры, сводка | ответы бота на `/start`, уведомления в Telegram |
| раздел курьера, карта | оплата картой (Click/Payme, Stripe) |
| все тесты бэкенда и фронтенда | |

Этого достаточно, чтобы изучать и менять код. Вход в магазин выполняется без Telegram:
мы сами сгенерируем «подписанные данные пользователя» (об этом в шаге 6).

## Из чего состоит проект

- **База данных PostgreSQL** хранит товары, заказы, курьеров.
- **Бэкенд** (папка `backend`, Python + FastAPI) — это API: правила магазина и работа с базой.
- **Фронтенд** (папка `frontend`, React) — страницы, которые открываются в браузере и обращаются к API.

Каждая часть запускается в своём окне терминала.

## Шаг 1. Установите программы (один раз)

1. **Python 3.12 или новее**: <https://www.python.org/downloads/>. В установщике отметьте
   **«Add python.exe to PATH»**.
2. **Node.js 22 LTS**: <https://nodejs.org/>. Все настройки по умолчанию.
3. **PostgreSQL 16**: <https://www.postgresql.org/download/windows/> → «Download the installer».
   - Пароль для пользователя `postgres` задайте **`postgres`**: так настроены файлы-примеры.
     Если зададите другой, поменяйте его в шаге 3.
   - Порт оставьте **5432**.
   - В конце установщик предложит запустить «Stack Builder». Он не нужен, снимите галочку.
4. **Git**: <https://git-scm.com/download/win>, чтобы скачать проект.

PostgreSQL после установки работает сам как служба Windows. Запускать его вручную не нужно.

Проверка: откройте **новое** окно PowerShell и выполните

```
python --version
node --version
git --version
```

Каждая команда должна напечатать номер версии.

## Шаг 2. Скачайте проект

```
cd $HOME\Desktop
git clone https://github.com/Shokhanasser1/10-D-tgbot.git
cd 10-D-tgbot
```

Дальше все команды выполняются из этой папки, если не сказано другое.

## Шаг 3. Настройки (файлы `.env`)

Файлы `.env` хранят настройки и секреты. В git их нет, поэтому создаём их из примеров:

```
copy backend\.env.example backend\.env
copy frontend\.env.example frontend\.env
```

Откройте `backend\.env` в редакторе и найдите строку `ADMIN_BOOTSTRAP_TELEGRAM_IDS=`. Допишите число:

```
ADMIN_BOOTSTRAP_TELEGRAM_IDS=111111
```

- **`111111` — ваш ID владельца магазина.** Можно взять любое число, но запомните его: оно понадобится
  в шаге 6. Владелец видит админку.
- **Токен бота в файле выдуманный** (`123456:dev-local-test-token`), так и должно быть. Настоящий бот
  для локальной работы не нужен: токен нужен только для подписи данных входа, и её выполняет наш же
  сервер.
- Оплата локально — **наличными** (`CASH_ON_DELIVERY_ENABLED=true`): для карт нужны Telegram или Stripe.
- Если в шаге 1 вы задали для PostgreSQL другой пароль, замените `postgres:postgres` в строках
  `DATABASE_URL` и `TEST_DATABASE_URL` на `postgres:ваш_пароль`.

## Шаг 4. Бэкенд: библиотеки и база (один раз)

```
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements-dev.txt
python -m scripts.create_databases
alembic upgrade head
python -m scripts.seed_demo_data
```

Что делает каждая команда:

- `python -m venv .venv` создаёт **виртуальное окружение**: отдельную папку с библиотеками только
  для этого проекта.
- `.venv\Scripts\activate` включает его. В начале строки появится `(.venv)`. Эту команду нужно
  повторять в **каждом новом окне**.
- `pip install -r requirements-dev.txt` устанавливает библиотеки проекта и библиотеки для тестов.
- `python -m scripts.create_databases` создаёт в PostgreSQL две базы: `storefront` для магазина
  и `storefront_test` для тестов.
- `alembic upgrade head` создаёт в базе таблицы (миграции).
- `python -m scripts.seed_demo_data` загружает демо-каталог с товарами и фото.

> Если PowerShell пишет, что выполнение сценариев отключено (`running scripts is disabled`), один раз
> выполните `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` и ответьте `Y`.

## Шаг 5. Запустите бэкенд (окно 1)

В том же окне (папка `backend`, `(.venv)` в начале строки):

```
uvicorn app.main:app --reload --port 8000
```

Бэкенд готов, когда появится строка `Application startup complete`. **Окно не закрывайте.**
Проверка: <http://localhost:8000/docs> показывает документацию API.

`--reload` перезапускает сервер сам, когда вы меняете код.

## Шаг 6. Вход без Telegram и запуск фронтенда (окно 2)

Внутри Telegram магазин получает от Telegram подписанные данные пользователя (`initData`).
В обычном браузере их нет, поэтому сгенерируем их сами для ID из шага 3.
Откройте **второе** окно PowerShell в папке проекта:

```
cd backend
.venv\Scripts\activate
python -m scripts.make_dev_init_data 111111 ru
```

Команда напечатает длинную строку. Откройте `frontend\.env` и вставьте её после
`VITE_DEV_MOCK_INIT_DATA=` (в одну строку, без кавычек). Строка действует **24 часа**, потом повторите
команду и перезапустите фронтенд.

Затем в том же окне:

```
cd ..\frontend
npm install
npm run dev
```

`npm install` нужен только в первый раз (и когда меняется `package.json`). **Окно не закрывайте.**

## Шаг 7. Откройте в браузере

| Адрес | Что должно быть |
|---|---|
| <http://localhost:5173> | магазин с каталогом, вверху шестерёнка (вы владелец) |
| <http://localhost:5173/admin> | админка: Сводка, Каталог, Заказы, Курьеры, Админы |
| <http://localhost:8000/docs> | документация API, запросы можно вызывать прямо со страницы |

Попробуйте оформить заказ: добавьте товар в корзину и оплатите **наличными**. Заказ сразу появится
в админке, в разделе «Заказы».

Тестовый заказ для раздела курьера (в окне с `(.venv)`, папка `backend`):

```
python -m scripts.seed_courier_demo --courier 222 --customer 111 --lat 41.31 --lng 69.24
```

## Шаг 8. Тесты

```
cd backend
.venv\Scripts\activate
pytest -q          # около минуты; нужен запущенный PostgreSQL

cd ..\frontend
npm test           # база не нужна
```

Все тесты должны пройти без ошибок.

## Остановить и запустить снова

- Остановить: `Ctrl+C` в окнах 1 и 2. PostgreSQL продолжит работать как служба Windows, это нормально.
- Запустить снова: шаг 5 (с `.venv\Scripts\activate`) и шаг 6 без `npm install`.
- После `git pull` (новая версия проекта) выполните в `backend` с `(.venv)`:
  `pip install -r requirements-dev.txt` и `alembic upgrade head`, а в `frontend`: `npm install`.

## Если что-то не работает

| Симптом | Причина | Решение |
|---|---|---|
| `python` / `node` не найден | программа не добавлена в PATH или окно открыто до установки | откройте новое окно; для Python переустановите с галочкой «Add to PATH» |
| `create_databases` пишет `could not reach PostgreSQL` | PostgreSQL не установлен, служба остановлена или пароль в `backend\.env` другой | Пуск → «Службы» → `postgresql-x64-16` → «Запустить»; проверьте пароль в `DATABASE_URL` |
| `password authentication failed` | пароль в `DATABASE_URL` не совпадает с заданным при установке | исправьте `postgres:пароль` в обеих строках `backend\.env` |
| `ConnectionRefusedError` в бэкенде или тестах | PostgreSQL не запущен | запустите службу (строка выше) |
| `SHOP_TIMEZONE ... is not a known IANA time zone` или `No module named ...` | библиотеки не установлены | `pip install -r requirements-dev.txt` с `(.venv)` |
| `address already in use`, порт 8000 или 5173 занят | сервер уже запущен в другом окне | закройте старое окно или нажмите там `Ctrl+C` |
| В магазине ошибка 401 или «Нет доступа» | строка в `frontend\.env` устарела (24 часа) или выдана для другого ID | повторите шаг 6 и перезапустите `npm run dev` |
| Каталог пустой | демо-данные не загружены | `python -m scripts.seed_demo_data` |
| Фото не показываются | бэкенд запущен не из папки `backend` | запускайте `uvicorn` из папки `backend` |
