# Запуск магазина в Telegram: пошаговая инструкция

Инструкция для урока. Она проводит через весь путь: от пустого компьютера до работающего
магазина в Telegram с админкой, оплатой через Stripe и возвратом денег. У каждого шага есть
объяснение, **зачем** он нужен: без этого ученики просто повторяют команды, не понимая их.

Все команды выполняются в папке проекта (`10-D-tgbot`), если не сказано другое.

---

## 0. Что мы запускаем

Магазин — это **Telegram Mini App**: веб-страница, которую Telegram открывает внутри чата
с ботом. Из чего он состоит:

```
 Покупатель / админ / курьер
          │  (Telegram или браузер)
          ▼
   ┌──────────────┐      /api/*       ┌──────────────┐      SQL      ┌────────────┐
   │ web (nginx)  │ ────────────────▶ │ api (FastAPI)│ ────────────▶ │ db         │
   │ сайт + фото  │                   │ вся логика   │               │ PostgreSQL │
   └──────────────┘                   └──────────────┘               └────────────┘
          ▲                                  ▲   ▲
          │ /media/ (фото товаров)           │   │ вебхуки: «оплачено», «возврат»
          └────── общий том media ───────────┘   └──────────── Stripe
                                                  └──────────── Telegram (геопозиция курьеров)
```

- **web**: nginx отдаёт сам сайт (React) и фото товаров, а запросы `/api/...` передаёт в api.
- **api**: бэкенд на Python (FastAPI). Каталог, корзина, заказы, курьеры, админка.
- **db**: база данных PostgreSQL. Все данные хранятся здесь.

Все три части запускаются одной командой через **Docker Compose**.

Как Telegram узнаёт пользователя. Открывая Mini App, Telegram передаёт сайту подписанные
данные о пользователе (`initData`). Сервер проверяет подпись токеном бота, поэтому подделать
«я — владелец» нельзя. Паролей в системе нет.

## 2. Создаём бота

1. Откройте в Telegram **@BotFather**.
2. Отправьте `/newbot`.
3. Введите название (например, `Cosmetics e-commerce`), затем username. Username должен
   заканчиваться на `bot`, например `ecosmetics10bot`.
4. BotFather пришлёт **токен** вида `1234567890:AAE...`.

**Токен — это пароль от бота.** Кто знает токен, тот управляет ботом и может подделывать
подписи пользователей. Поэтому:
- не публикуйте токен в чатах, на скриншотах и в git;
- если токен утёк, отправьте BotFather `/revoke`, выберите бота и получите новый. Старый токен
  сразу перестанет работать, и новый нужно вписать в `.env` (шаг 4).

---

## 3. Узнаём свой Telegram ID

Напишите боту **@userinfobot**, он ответит числом, например `665823713`. Это ваш Telegram ID.
Он нужен, чтобы система с первого запуска знала, кто владелец магазина.

## 4. Файл настроек `.env`

Все настройки и секреты хранятся в файле `.env` в корне проекта. Он **не попадает в git**
(указан в `.gitignore`), поэтому секреты не утекут вместе с кодом.

### 4.1. Создаём файл

```
copy .env.example .env        # Windows (cmd / PowerShell)
cp .env.example .env          # macOS / Linux / Git Bash
```

`.env.example` — шаблон со всеми переменными и комментариями. В `.env` мы вписываем свои значения.

### 4.2. Генерируем секреты

Секрет — длинная случайная строка, которую невозможно угадать. Сгенерируйте **три разных** секрета:

```
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Команду нужно запустить три раза, у каждого секрета своя строка.

### 4.3. Заполняем переменные

| Переменная | Что вписать | Зачем |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | токен из шага 2 | сервер проверяет им подписи Telegram |
| `TELEGRAM_BOT_USERNAME` | username бота без `@` | кнопка «Войти через Telegram» и ссылки на бота |
| `INTERNAL_API_TOKEN` | секрет №1 | доступ скриптов к админ-API (как владелец) |
| `ADMIN_SESSION_SECRET` | секрет №2 | подписывает вход в админку из браузера |
| `TELEGRAM_WEBHOOK_SECRET` | секрет №3 (только буквы, цифры, `_`, `-`) | чтобы геопозицию курьеров мог присылать только Telegram |
| `ADMIN_BOOTSTRAP_TELEGRAM_IDS` | ваш ID из шага 3 | при запуске этот человек становится владельцем |
| `SHOP_TIMEZONE` | `Asia/Tashkent` | по этому поясу считается «сегодня» в сводке |
| `MAP_DEFAULT_CENTER` | `41.3111,69.2797` | где открывается карта (здесь — Ташкент) |
| `POSTGRES_PASSWORD` | ещё один секрет (см. ниже) | пароль базы данных |
| `STRIPE_*` | заполним в шаге 9 | оплата и возвраты |

Пример готового фрагмента (значения выдуманные):

```
TELEGRAM_BOT_TOKEN=1234567890:AAExampleExampleExample
TELEGRAM_BOT_USERNAME=ecosmetics10bot
INTERNAL_API_TOKEN=Qw3...длинная_строка...
ADMIN_SESSION_SECRET=Zx9...другая_длинная_строка...
TELEGRAM_WEBHOOK_SECRET=Lm2...третья_строка...
ADMIN_BOOTSTRAP_TELEGRAM_IDS=665823713
SHOP_TIMEZONE=Asia/Tashkent
MAP_DEFAULT_CENTER=41.3111,69.2797
```

> **Пароль базы задаётся до первого запуска.** PostgreSQL запоминает пароль при создании базы.
> Если базу уже запускали со старым паролем, новый `POSTGRES_PASSWORD` в `.env` не применится,
> и api не сможет подключиться. Чтобы сменить пароль у существующей базы:
> ```
> docker compose exec db psql -U postgres -c "ALTER USER postgres PASSWORD 'новый_пароль';"
> ```
> После этого впишите тот же пароль в `.env` и перезапустите: `docker compose up -d`.

Несколько владельцев указываются через запятую: `ADMIN_BOOTSTRAP_TELEGRAM_IDS=111,222`.
Остальных админов (менеджеров, диспетчеров) потом добавляют прямо из админки.

## 5. Запуск

```
docker compose up -d --build
```

- `up`: поднять сервисы.
- `-d`: в фоне, чтобы терминал остался свободным.
- `--build`: собрать образы заново. **Обязательно после каждого изменения `.env`, которое
  касается сайта** (`TELEGRAM_BOT_USERNAME`, `STRIPE_PUBLISHABLE_KEY`, `MAP_*`): эти значения
  встраиваются в сайт при сборке.

Что происходит при запуске:
1. Поднимается база данных.
2. api применяет **миграции**: создаёт и обновляет таблицы.
3. api создаёт владельца из `ADMIN_BOOTSTRAP_TELEGRAM_IDS`. Если владелец уже есть, ничего не меняется.
4. Запускается nginx с сайтом.

Проверка:

```
curl http://localhost:8080/api/health
```

Ответ `{"status":"ok"}` означает, что всё работает. Сайт открывается по адресу <http://localhost:8080>.

Если без `ADMIN_SESSION_SECRET` или `INTERNAL_API_TOKEN` запуск останавливается с ошибкой
«required variable ... is missing», это нормально: так система защищает от запуска без секретов.

### Демо-товары (по желанию)

```
docker compose exec api python -m scripts.seed_demo_data
```

`docker compose exec api` означает «выполнить команду внутри контейнера api».

## 6. Почему в обычном браузере магазин «пустой»

Откройте <http://localhost:8080> в браузере. Сайт загрузится, но каталог не покажется. Это
правильно: вне Telegram нет подписанных данных пользователя (`initData`), и сервер не знает, кто
вы. Магазин нужно открывать **из Telegram**, а для этого нужен HTTPS (следующий шаг).

**Админку** можно открыть и в браузере, через вход с Telegram (шаг 8.2).

---

## 7. HTTPS: даём магазину публичный адрес

Telegram открывает Mini App только по `https://`. Варианты:

- **Для урока: туннель.** Временный https-адрес, который ведёт на ваш компьютер.
- **Для настоящего магазина: сервер и домен** с HTTPS-сертификатом (например, от Let's Encrypt).

### 7.1. Туннель cloudflared (бесплатно, без регистрации)

1. Скачайте `cloudflared`:
   <https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/>
2. Запустите:
   ```
   cloudflared tunnel --url http://localhost:8080
   ```
3. В выводе появится адрес вида `https://random-words.trycloudflare.com`. Это и есть адрес магазина.

> Адрес туннеля **меняется при каждом запуске**. После перезапуска `cloudflared` шаги 7.2 и 8.2
> нужно повторить с новым адресом. Окно с `cloudflared` должно оставаться открытым.

Альтернатива — `ngrok http 8080`, он работает так же, но требует регистрации.

### 7.2. Привязываем Mini App к боту

Проще всего — одной командой (нужен `TELEGRAM_WEBHOOK_SECRET` в `.env`, см. раздел 10):

```
docker compose exec api python -m scripts.set_telegram_webhook https://адрес-из-шага-7.1
```

Она делает две вещи: подключает вебхук (через него бот получает `/start` и геопозиции курьеров)
и ставит боту **кнопку меню**, которая открывает магазин. Если ещё записать тот же адрес в `.env`
как `WEBAPP_URL=https://адрес-из-шага-7.1/` и перезапустить `api`, бот будет отвечать на `/start`
приветствием и кнопкой «Открыть магазин» — на русском, узбекском или английском, по языку Telegram
пользователя.

Вручную то же самое можно сделать в **@BotFather**: `/mybots` → выберите бота → **Bot Settings** →
**Menu Button** → отправьте https-адрес и название кнопки, например `Магазин`.

Теперь в чате с ботом появится кнопка, которая открывает магазин.

## 8. Вход в админку

### 8.1. Из Telegram (основной способ)

Откройте магазин кнопкой в чате с ботом. Владелец и другие админы видят в верхней панели
**шестерёнку**: она ведёт в админку. Остальные пользователи её не видят.

### 8.2. Из браузера на компьютере

Нужно один раз разрешить боту вход на ваш домен:

1. В **@BotFather** отправьте `/setdomain`.
2. Выберите бота и отправьте домен **без** `https://`, например `random-words.trycloudflare.com`.
3. Откройте в браузере `https://ваш-адрес/admin`.
4. Нажмите **«Войти через Telegram»** и подтвердите вход в Telegram.

Вход действует 12 часов. Если владелец отключит админа, тот теряет доступ сразу, не дожидаясь
конца сессии.

### 8.3. Роли

| Раздел | Владелец | Менеджер каталога | Диспетчер |
|---|:-:|:-:|:-:|
| Сводка (выручка, остатки, топ товаров) | ✓ | | |
| Каталог: товары, варианты, фото, переводы, категории | ✓ | ✓ | |
| Заказы: просмотр, отмена с возвратом денег | ✓ | | ✓ |
| Курьеры, доставки, карта | ✓ | | ✓ |
| Админы | ✓ | | |

Добавить админа: **Админы** → Telegram ID человека (он узнаёт его у @userinfobot) → имя → роль.
Добавить курьера: **Курьеры** → Telegram ID → имя. Покупатель увидит это имя, поэтому указывайте
только имя, без фамилии.

В магазине всегда остаётся хотя бы один активный владелец: система не даст отключить
последнего. Отключить самого себя тоже нельзя.

## 9. Stripe: оплата и возвраты

Stripe принимает оплату картой. Схема работы:
1. Покупатель платит внутри Mini App.
2. Stripe сообщает серверу «оплачено» через **вебхук**: это запрос от Stripe на наш адрес.
3. Только после этого заказ становится оплаченным и попадает курьерам. Браузеру покупателя
   сервер не верит.
4. Когда админ отменяет заказ, сервер просит Stripe вернуть деньги, и Stripe вебхуком сообщает,
   чем закончился возврат.

### 9.1. Ключи (тестовый режим)

1. Войдите в <https://dashboard.stripe.com> и включите **Test mode** (переключатель вверху).
2. **Developers → API keys** — скопируйте:
   - `Publishable key` (`pk_test_...`) → `STRIPE_PUBLISHABLE_KEY` в `.env`;
   - `Secret key` (`sk_test_...`) → `STRIPE_SECRET_KEY` в `.env`.

Secret key — секрет, его нельзя показывать. Publishable key публичный, он встраивается в сайт.

### 9.2. Вебхук

1. **Developers → Webhooks → Add endpoint**.
2. Endpoint URL: `https://ваш-адрес/api/webhooks/stripe`.
3. **Select events** — отметьте пять событий:
   - `payment_intent.succeeded` — оплата прошла;
   - `payment_intent.payment_failed` — оплата не прошла;
   - `refund.created`, `refund.updated`, `refund.failed` — как идёт возврат денег.
4. Сохраните и откройте endpoint. **Signing secret** (`whsec_...`) → `STRIPE_WEBHOOK_SECRET` в `.env`.

По этой подписи сервер проверяет, что вебхук действительно от Stripe, а не подделка.

Примените настройки:

```
docker compose up -d --build
```

### 9.3. Вариант без домена: Stripe CLI

Для проверки на своём компьютере вместо шага 9.2 можно использовать Stripe CLI:

```
stripe login
stripe listen --forward-to localhost:8080/api/webhooks/stripe
```

CLI напечатает `whsec_...`: впишите его в `STRIPE_WEBHOOK_SECRET` и перезапустите стек.
Окно с `stripe listen` должно оставаться открытым.

### 9.4. Проверка оплаты и возврата

1. Откройте магазин в Telegram, положите товар в корзину и оформите заказ.
2. Оплатите тестовой картой: номер `4242 4242 4242 4242`, срок — любая будущая дата, CVC — любые 3 цифры.
3. В админке: **Заказы** → новый заказ в статусе «Оплачен».
4. Нажмите **«Отменить и вернуть деньги»**, укажите причину и подтвердите.
5. Статус возврата меняется: «Возврат в процессе» → «Деньги возвращены».
6. В Stripe Dashboard → **Payments** у платежа появится отметка *Refunded*.

Если в заказе стоит «Ошибка возврата», проверьте ключи Stripe и нажмите «Повторить возврат».
Вернуть больше, чем заплачено, Stripe не даст, так что двойного возврата не будет.

## 9a. Уведомления в Telegram

Бот сам пишет людям о заказах:
- покупателю — о каждом шаге заказа: оплачен, курьер принял, в пути, доставлен, время оплаты истекло, отменён магазином, деньги возвращены;
- курьерам — о новом заказе в пуле;
- владельцу и диспетчерам — о каждом новом оплаченном заказе;
- владельцу — если возврат денег не прошёл.

Чтобы это работало, нужны три вещи:
1. `TELEGRAM_BOT_TOKEN` в `.env` (он уже есть);
2. `WEBAPP_URL=https://ваш-адрес/` — кнопки в сообщениях открывают магазин по этому адресу;
3. человек хоть раз открывал чат с ботом. Telegram не даёт боту писать первым. Магазин после
   оформления заказа сам спросит «Разрешить боту писать вам?».

Посмотреть, что отправлено:
```
docker compose exec db psql -U postgres -d storefront -c "select created_at, chat_id, kind, status, last_error from notifications order by id desc limit 20"
```
Статус `undeliverable` значит, что человек не открывал чат с ботом или заблокировал его.

## 10. Курьеры и геопозиция (по желанию)

Курьер делится в чате с ботом **трансляцией геопозиции** (Live Location), и Telegram присылает
её серверу. Для этого серверу нужен вебхук Telegram:

```
docker compose exec api python -m scripts.set_telegram_webhook https://ваш-адрес
docker compose exec api python -m scripts.set_telegram_webhook --info
```

Вторая команда показывает, что видит Telegram. Если что-то не так, смотрите поле
`last_error_message`. Подробности — в `README.md`, раздел «Couriers & tracking».

## 11. Сценарий для урока

Полный путь заказа за 10–15 минут:

1. **Владелец** добавляет в админке категорию, товар, вариант с остатком и фото.
2. **Покупатель** открывает магазин в Telegram, покупает товар тестовой картой.
3. **Владелец** в сводке видит выручку, а в заказах — новый заказ.
4. **Курьер** (второй Telegram-аккаунт, добавленный в «Курьеры») берёт заказ в разделе курьера.
5. **Диспетчер** видит доставку в «Курьеры → Доставки».
6. Вариант А: курьер забирает и доставляет заказ, покупатель следит за ним на карте.
   Вариант Б: до того как курьер забрал заказ, владелец отменяет его, и деньги возвращаются.

Вопросы ученикам:
- Почему заказ становится «оплаченным» только после вебхука, а не когда браузер сказал «оплачено»?
- Почему отменить заказ можно только до того, как курьер его забрал?
- Что будет, если два курьера одновременно нажмут «Взять заказ»? (Только один получит заказ.)
- Зачем серверу удалять из фотографий метаданные EXIF? (В фото с телефона бывают GPS-координаты
  места съёмки.)

## 12. Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `required variable ... is missing` при запуске | в `.env` не заполнен обязательный секрет | заполните и запустите снова |
| В браузере каталог пустой | вне Telegram нет `initData` | открывайте магазин из Telegram |
| Кнопка магазина в Telegram не открывается | адрес не https или туннель перезапущен | обновите Menu Button (шаг 7.2) |
| «Нет доступа» в админке | ваш ID не среди админов | проверьте `ADMIN_BOOTSTRAP_TELEGRAM_IDS` и перезапустите api |
| Кнопка «Войти через Telegram» пишет *Bot domain invalid* | не выполнен `/setdomain` или сменился адрес туннеля | повторите шаг 8.2 |
| «Вход через браузер не настроен» | пустой `TELEGRAM_BOT_USERNAME` при сборке | впишите и выполните `docker compose up -d --build` |
| Заказ не становится «Оплачен» | вебхук Stripe не доходит | проверьте URL, событие `payment_intent.succeeded` и `STRIPE_WEBHOOK_SECRET` |
| «Ошибка возврата» | неверный `STRIPE_SECRET_KEY` или платёж не из этого аккаунта | исправьте ключ и нажмите «Повторить возврат» |
| api не стартует после смены `POSTGRES_PASSWORD` | база создана со старым паролем | см. врезку в шаге 4.3 |
| Фото не загружается | файл больше 10 МБ или не JPEG/PNG/WebP | уменьшите файл или сохраните в JPEG |

Логи — первое место, куда смотреть:

```
docker compose logs -f api      # бэкенд
docker compose logs -f web      # nginx
```

## 13. Повседневные команды

```
docker compose up -d --build    # запустить / применить изменения
docker compose ps               # что запущено
docker compose logs -f api      # логи бэкенда (Ctrl+C — выйти)
docker compose stop             # остановить, данные сохраняются
docker compose down             # удалить контейнеры, данные сохраняются
docker compose down -v          # ОСТОРОЖНО: удалит ещё и базу, и фото
```

Данные хранятся в двух **томах** Docker: `pgdata` (база) и `media` (фото товаров). Для
настоящего магазина их нужно регулярно сохранять (бэкап).

## 14. Безопасность: итог

- `.env` никогда не коммитится и не пересылается в чатах.
- Утёк токен бота — `/revoke` в @BotFather и новый токен в `.env`.
- Утёк `ADMIN_SESSION_SECRET` — сгенерируйте новый. Все входы из браузера станут
  недействительными, и админам придётся войти заново.
- Для настоящего магазина используются боевые ключи Stripe (`sk_live_...`) только на сервере
  с HTTPS, сильный пароль базы, свой домен и сервис карт вместо публичного OpenStreetMap
  (`MAP_TILE_URL`).
