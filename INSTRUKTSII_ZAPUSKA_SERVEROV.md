# Инструкции запуска серверов (локально)

Как самому запустить магазин на своём компьютере и проверить, что всё работает.

> Нет Docker (например, у учеников)? Смотрите [`ZAPUSK_BEZ_DOCKER.md`](ZAPUSK_BEZ_DOCKER.md):
> там PostgreSQL ставится обычным установщиком, а всё остальное запускается так же.

Есть два способа:

| | Способ А — режим разработки | Способ Б — всё в Docker |
|---|---|---|
| Для чего | проверять и разрабатывать в обычном браузере | проверить магазин в самом Telegram, как на сервере |
| Вход | автоматически, как владелец (без Telegram) | только через Telegram (нужен https-туннель) |
| Бот (`/start`, уведомления, оплата картой) | не работает: токен выдуманный | работает после шагов ниже |
| Адрес | <http://localhost:5173> | <http://localhost:8080> |

Для проверки удобнее **способ А**.

Все команды выполняются в PowerShell из папки проекта `E:\Desktop\10-D-tgbot`, если не сказано другое.
Docker Desktop должен быть запущен.

---

## Способ А: режим разработки

Понадобятся **три окна терминала**.

### Окно 1: база данных

Docker-версию сайта нужно остановить, потому что она занимает те же порты. Базу оставляем:

```
docker compose stop api web
docker compose up -d db
```

### Окно 2: бэкенд (API)

```
cd backend
.venv\Scripts\activate
pip install -r requirements-dev.txt
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

- `pip install -r requirements-dev.txt` доустанавливает библиотеки, которые появились в проекте после
  создания `.venv`. Если ничего не изменилось, команда просто ничего не сделает.
- `alembic upgrade head` приводит таблицы базы к последней версии.
- `--reload` перезапускает сервер сам, когда меняется код.

Бэкенд готов, когда появится строка `Application startup complete`. **Окно не закрывайте.**

### Окно 3: вход без Telegram, затем сайт

Вне Telegram нет подписанных данных пользователя, поэтому сгенерируем их для своего ID:

```
cd backend
.venv\Scripts\activate
python -m scripts.make_dev_init_data 665823713 ru
```

Команда напечатает длинную строку. Откройте `frontend\.env` и вставьте её после
`VITE_DEV_MOCK_INIT_DATA=`. Строка действует **24 часа**, потом повторите команду.

Затем в том же окне:

```
cd ..\frontend
npm run dev
```

**Окно не закрывайте.**

### Что проверить в браузере

| Адрес | Что должно быть |
|---|---|
| <http://localhost:5173> | магазин с каталогом и шестерёнкой вверху (вы админ) |
| <http://localhost:5173/admin> | админка: Сводка, Каталог, Заказы, Курьеры, Админы |
| <http://localhost:8000/docs> | документация API, запросы можно вызывать прямо со страницы |

Сценарий проверки:

1. **Каталог** → откройте товар → добавьте фото → оно должно появиться.
2. **Магазин** → положите товар в корзину → оформите заказ **наличными**. Заказ сразу получит статус
   «Оплачен» и появится в админке в «Заказах» с пометкой «Наличные».
3. **Заказы** → откройте этот заказ → «Отменить». Он станет «Отменён»; возвращать нечего, потому что
   деньги за наличный заказ ещё не брали.
4. Смените язык на RU в правом верхнем углу.
5. Сузьте окно браузера: меню переедет вниз, как на телефоне.

Если при оформлении написано «В магазине пока не настроена оплата», проверьте, что в `backend\.env`
есть строка `CASH_ON_DELIVERY_ENABLED=true`, и перезапустите бэкенд.

Если заказов нет, создайте тестовый (в окне с активированным `.venv`, в папке `backend`):

```
python -m scripts.seed_courier_demo --courier 222 --customer 111 --lat 41.31 --lng 69.24
```

Если нет товаров, загрузите демо-каталог:

```
python -m scripts.seed_demo_data
```

### Остановить

`Ctrl+C` в окнах 2 и 3. База продолжит работать в Docker, это не мешает.

## Способ Б: всё в Docker, как на сервере

```
docker compose up -d --build
```

- Сайт: <http://localhost:8080>
- Проверка: `curl http://localhost:8080/api/health` должна вернуть `{"status":"ok"}`

В обычном браузере каталог здесь будет **пустым**, и в админку не войти: этот режим ждёт
настоящего входа через Telegram. Чтобы магазин и бот заработали в Telegram, нужен https-туннель
(подробно — `docs/LAUNCH_GUIDE_RU.md`, шаги 7–8).

### Подключить бота (после каждого нового адреса туннеля)

1. Отдельное окно, **не закрывать** (адрес меняется при каждом запуске):
   ```
   cloudflared tunnel --url http://localhost:8080
   ```
   Скопируйте адрес вида `https://random-words.trycloudflare.com`.
2. В корневом `.env` замените строку `WEBAPP_URL=` на новый адрес (со слешем в конце) и примените:
   ```
   docker compose up -d api
   ```
3. Зарегистрируйте вебхук и кнопку меню бота:
   ```
   docker compose exec api python -m scripts.set_telegram_webhook https://новый-адрес
   docker compose exec api python -m scripts.set_telegram_webhook --info
   ```
   В `url` должен быть новый адрес. Теперь бот отвечает на `/start`.

Полезные команды:

```
docker compose ps               # что запущено
docker compose logs -f api      # логи бэкенда (Ctrl+C — выйти)
docker compose stop             # остановить всё (данные сохраняются)
```

## Переключение между способами

- **Из Б в А:** `docker compose stop api web`, затем окна 2 и 3 из способа А.
- **Из А в Б:** закройте окна 2 и 3 (`Ctrl+C`), затем `docker compose up -d`.

Одновременно оба способа работать не могут: они используют один и тот же порт 8000.

## Тесты

```
cd backend
.venv\Scripts\activate
pytest -q                       # ~1 минута, нужна запущенная база

cd ..\frontend
npm test                        # база не нужна
```

Должно быть примерно **508** (бэкенд) и **330** (фронтенд) пройденных тестов, без ошибок.

## Если что-то не работает

| Симптом | Причина | Решение |
|---|---|---|
| `address already in use`, порт 8000 занят | Docker-версия ещё запущена | `docker compose stop api web` |
| `ports are not available ... 8000` при `docker compose up` | ещё работает `uvicorn` из способа А (иногда остаётся его фоновый процесс `python`) | `Ctrl+C` в окне бэкенда; если не помогло — закройте лишние процессы `python` в диспетчере задач |
| Бот молчит на `/start` | вебхук не зарегистрирован или туннель перезапущен; в способе А бот не работает вообще | способ Б и шаги «Подключить бота» |
| «В магазине пока не настроена оплата» | не включён ни один способ оплаты | `CASH_ON_DELIVERY_ENABLED=true` в `backend\.env` (способ А) или в `.env` (способ Б) |
| В админке «Нет доступа» или ошибка 401 | строка в `frontend\.env` устарела (24 часа) или выдана не для вашего ID | повторите `make_dev_init_data`, перезапустите `npm run dev` |
| `SHOP_TIMEZONE 'Asia/Tashkent' is not a known IANA time zone` или `No module named ...` | в `.venv` не хватает библиотек (в Windows нет своей базы часовых поясов, её даёт пакет `tzdata`) | `pip install -r requirements-dev.txt` в активированном `.venv` |
| `ConnectionRefusedError` в бэкенде или тестах | база не запущена | откройте Docker Desktop, затем `docker compose up -d db` |
| `docker: command not found` / ошибка подключения к Docker | Docker Desktop не запущен | запустите Docker Desktop и подождите 1–2 минуты |
| Каталог пустой на <http://localhost:5173> | в базе нет товаров | `python -m scripts.seed_demo_data` |
| Фото не показывается | бэкенд запущен не из папки `backend` | запускайте `uvicorn` из папки `backend` (фото лежат в `backend\media`) |

## Что где настроено

- `backend\.env`: настройки бэкенда для разработки (способ А), в том числе ваш ID владельца
  (`ADMIN_BOOTSTRAP_TELEGRAM_IDS=665823713`), выдуманный токен бота, `ADMIN_COOKIE_SECURE=false`,
  `MEDIA_ROOT=./media`, `SHOP_TIMEZONE=Asia/Tashkent`, оплата наличными
  (`CASH_ON_DELIVERY_ENABLED=true`) и выключенная отправка уведомлений (`NOTIFICATION_SEND_SECONDS=0`).
- `frontend\.env`: адрес API (`http://127.0.0.1:8000`) и строка входа `VITE_DEV_MOCK_INIT_DATA`.
- `.env` в корне: настройки для Docker (способ Б): настоящий токен бота, секреты, владелец,
  `WEBAPP_URL` (адрес туннеля). Способы оплаты и валюта — см. `docs/LAUNCH_GUIDE_RU.md`, шаги 4.3 и 8a.

Все три файла `.env` в git не попадают. Никому их не пересылайте.
